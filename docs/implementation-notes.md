기준은 14 MVP 정의와 15 구현을 우선하는 것이다.

| 항목 | 충돌 | 판단 |
|---|---|---|

| 실행 상태 | 07·14는 3개, 10-1·11·12는 2개 | `PARTIALLY_EXECUTED`를 포함한 3개 |
| 필드 이름 | 12는 `status`, `memo`, 07·15는 `state`, `insight` | `state`, `insight` |

| 진행 중 정렬 | 09·10은 최근 활동순, 11·12·14는 생성일순 | 생성일 최신순 |
| 휴지통 복구 | 11은 복수 선택, 14·15는 개별과 전체 | 개별과 전체 |

## 설계에 없어서 새로 내린 판단

형식: 기존 기준 → 구현 중 발견 → 판단 → 변경 내용 → 변경 이유

1. **이어서 작성할 단계**: 저장 방식 미확정 → 13이 임의 필드 추가를 금지 → 저장하지 않고 계산 → 필수값이 비어 있는 첫 단계, 모두 채워졌으면 ⑦ → 데이터 구조를 늘리지 않기 위해.
2. **이전 단계로 이동할 때의 저장**: 저장한다는 규칙만 있음 → 필수값이 비어 있을 수 있음 → 입력한 만큼 저장 → 필수값 검사는 다음 단계로 갈 때만 수행 → 뒤로 가는 것만으로 입력을 잃거나 막히지 않게 하기 위해.
3. **상황을 비우는 경우**: 상황은 필수 → 저장된 PLAY에서 지울 수 있음 → 새 PLAY는 생성하지 않고, 저장된 PLAY는 저장을 거부 → 상황이 PLAY의 식별 정보이기 때문.
4. **완료 PLAY 수정 중 이탈**: 08·09·10에서 보류 → 작성 중과 같은 흐름 필요 → 같은 확인 창 사용 → 완료 상태와 최초 완료 시각 유지 → 사용자가 익힌 동작을 하나로 유지하기 위해.
5. **완료 PLAY의 필수값**: 입력 조건 충족만 규정 → 비운 채 저장하면 완료 조건이 깨짐 → 저장 거부 → 완료 PLAY의 무결성을 지키기 위해.
6. **휴지통과 백업 위치**: 09에서 보류, 15-04는 메인 메뉴 외부 → Footer의 "관리"에 배치 → 판단 흐름과 관리 기능을 분리하기 위해.
7. **손상된 저장 데이터**: 규정 없음 → 빈 목록으로 처리하면 다음 저장 때 덮어씀 → 읽기와 쓰기를 중단하고 복원 경로 안내 → 사용자 기록을 보호하기 위해.
8. **가져오기 확인**: 15-11은 확인 절차를 명시하지 않음 → 기존 데이터가 되돌릴 수 없이 교체됨 → 교체 전 확인 창 추가 → 영구 삭제와 같은 수준의 보호가 필요하기 때문.
9. **이탈 확인 조건**: 11은 내용이 있으면 확인, 14는 저장되지 않은 변경이 있으면 경고 → 변경이 없으면 잃을 내용이 없음 → 저장되지 않은 변경이 있을 때만 확인 → 불필요한 확인을 줄이기 위해.
10. **문제 검색**: 원문 포함 여부로 규정 → 영문 대소문자를 구분하게 됨 → 규정대로 유지 → 설계와 다르게 해석하지 않기 위해. 사용 중 불편하면 재검토한다.

## 기술 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 라우터 | React Router 7 데이터 라우터 | 6에서 보안 권고가 있었고, 이탈 확인에 `useBlocker`가 필요 |
| Vite | 6 | 현재 개발 환경의 Node 20.14 지원 |
| Vitest | 4 | 3의 보안 권고 해결, 5는 Node 22 이상 필요 |
| E2E의 CI 포함 | 제외 | HOLD-002 |

npm 10.8.1에서는 `npm install`이 `edgesOut` 오류로 실패한다. `npm ci`는 정상이며, 의존성을 바꿀 때는 npm 10.9 이상을 사용한다.

## 테스트 결과

- 단위 테스트: 54개 통과
- Playwright E2E: 42개 통과 (Chromium, 3회 반복 실행)
- 확인 범위: 15-13의 테스트 대상과 15-12의 통합 확인 항목, 저장 실패, 손상 데이터, 입력값의 스크립트 미실행
- GitHub Actions: 첫 푸시(`09b898b`)에서 설치, 빌드, 단위 테스트 통과. E2E는 CI에 포함하지 않는다.
- 미확인: Chromium 외 브라우저

## 구현 중 발견한 문제

- E2E에서 화면 전환 전에 버튼을 찾아 간헐적으로 실패 → 화면 전환을 기다리도록 테스트 수정 → 전체 3회 반복 통과. 앱 결함은 아니다.
- `npm audit`에서 라우터와 Vitest의 취약점 발견 → 위 기술 결정대로 업그레이드 → 0건.
